# T9 manual-position contract v2, 1.4.0

This is an explicit product-contract change authorized by the new instruction. The earlier question-or-Please filter was an implementation restriction; there is no visible literal user instruction requiring only questions. It prevented natural answers despite the user's request for conversation T9. v2 treats neutrality as **no automatic assertion/selection/sending/speech by the app**, rather than a grammatical ban on affirmative or negative drafts.

Reply options now require en, ru and kind: positive, negative, clarify or uncertain. They are POSSIBLE USER POSITIONS, labelled «Да / подходит», «Нет / не подходит», «Уточнить», «Не знаю / проверить». The user chooses what is true for them. New choices are visibly expanded; English remains unselected until a click. Selected English is preserved and may be edited. Selection never updates own_response_state.spoken, which remains unknown. No automatic call action, microphone or sending is added.

Hearing, subjective state and proposed actions can offer direct yes/no-style alternatives alongside a clarification. A negative hearing alternative is no longer rejected merely because the app has not observed an audio fault: it is explicitly the user's possible position. A clarification that presupposes an unobserved fault remains rejectable. Unknown factual answers (price/number/address/clock/biography/completed action) get uncertainty/verification rather than guessed specifics. Concrete amounts/times/biography/payment promises are bounded by additional lexical validation. Explicit typed intent retains the user's supplied position and is not replaced by contradictory alternatives.

Latest target, bounded reference context, terminal/full-JSON checks, stale revisions, one inflight request, at most two starts per 12 seconds, reservation before credentials/dispatch, no same-context retry and Stop remain. Schema requires the visible kind; undocumented two-field automatic-reply responses fail, rather than silently becoming statements. Translation of explicitly typed intent retains its original EN/RU schema. Financial and capture consents are unchanged.

Offline fixtures include hearing, a break, joining an activity, changed online/in-person conditions, polite refusal, unknown author, price ambiguity, train time, completed task and a one-word place follow-up. They test validation/contracts, not generation quality. Conservative lexical policy is not a complete semantic detector; mistaken ASR, wrong type, implied promises or unsupported facts can still occur. User review is required. Model-generated positions are never evidence about the user's actual situation.

Historical account balances, spending authorizations and request-cost details are omitted from the public snapshot. Earlier test observations are historical; no live provider verification is claimed by this publication.
