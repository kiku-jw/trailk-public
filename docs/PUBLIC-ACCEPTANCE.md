# Trailk 1.2.1: тихая публичная проверка 3 октября

Реально выполнено: 99.2 секунды PCM из 35 секунд публичной ирландской речи CC BY 4.0 и синтетических английских вопросов о встрече, расписании, поезде/автобусе с паузами. PCM шёл с реальной скоростью через Unix socket → NativeReceiver → dedicated OpenAI translation WebSocket → автоматический ReplyScheduler → OpenAI Responses. Ручной ввод мысли и кнопка ответа не использовались. Публичный источник изолирован в отдельной директории; Zoom, пользовательские разговоры, браузерные вкладки и микрофон не захватывались.

Первый RU-текст появился примерно через 1.403 секунды от первого PCM; соединение подготовлено за 2.402 секунды от запуска. Это единичное измерение публичного файла, не гарантия задержки Zoom. При 284 дельтах было 5 автоматических текстовых запросов, минимальный интервал 12.047 секунды; ответы API заняли 1.474–2.438 секунды. Исходная сборка показала только 2 блока из 5, первый через 82.368 секунды от запуска: остальные отбрасывались при продолжении речи. Ошибка устранена: быстро полученный ответ к предыдущей реплике показывается с явной отметкой устаревшего контекста, без замены выбранного английского; результат старше 8 секунд при изменившемся контексте отбрасывается. Stop по-прежнему отменяет показ. Дополнительно исправлено изменение статуса поздним успехом/ошибкой после Stop; обе ветки регрессионно проверены.

Отдельно устранено ожидание паузы во всей речи: завершённое содержательное предложение допускает запрос после 1.6 секунды устойчивости завершённого контекста, даже если затем поступает новый незаконченный фрагмент. Новые дельты сами запросов не создают: 12 секунд между запусками, один запрос одновременно, дедупликация контекста, расходный guard. Это изменение проверено локальными регрессиями; финальный scheduler повторно платно не прогонялся.

Реальный тест выявил, что общий prompt режимов заставлял модель пересказывать собеседника и иногда придумывать предпочтение пользователя. Теперь reply получает отдельную инструкцию отвечать слушателю по последнему вопросу, не переводить слова собеседника и не выдумывать его доступность/решения. Два реальных повторных запроса на том же публичном тексте дали преимущественно вопросы: «What time does it end?», «Could you repeat the schedule?», «How long does each take?». Задержки 1.069 и 1.639 секунды. Качество не гарантировано: встречались менее подходящие варианты, например «No questions, thank you» и вопрос о расписании в теме транспорта. По результату добавлен локальный фильтр для пустой мысли: остаются только вопросы/просьбы, минимум два. «No questions, thank you» исключён; это проверено на сохранённых реальных ответах без новой оплаты. Семантическую точность вопроса фильтр не гарантирует. Черновик выбирает человек; никакой отправки/озвучивания нет.

UI: новая группа начинается с первой карточки; чтение/наведение сохраняет прокрутку, выбранная карточка выделена, выбранный английский не заменяется. Старые строки и группы не перерисовываются. Source/budget настройки сохраняются, отдельного окна перед Start и выбора минут нет.

Отдельный настоящий CoreAudio-тест: private process tap только собственного тестового приложения, CATapMuted. 5.8 секунды/29 ненулевых PCM-кадров получены локально; аппаратный output этого процесса отключён самим tap, системная громкость не менялась. Перед включением tap проигрыватель имел volume=0; при завершении проигрыватель остановлен перед уничтожением tap. В облако этот native тест не отправлялся. ОС-диалог и широкое разрешение экрана не запрашивались программно; формулировка/атрибуция разрешения визуально не подтверждалась. Изоляция приватного Zoom/другого реально звучащего приложения, AirPods/device change не доказана этим тестом.

## Расход и предел доказательства

Historical account balances, spending authorizations and request-cost details are omitted from the public snapshot. Earlier test observations are historical; no live provider verification is claimed by this publication.

Полный native tap → cloud → final UI/T9 в одном прогоне не измерен: native проверен отдельно локально, облачный путь — от цифрового публичного PCM. Исторические сведения о разрешённых расходах и остатке счёта не включены в публичную копию.

Реальный длительный Zoom, истечение/продление API, реальные отключения сети/устройства, микрофон и диаризация не испытаны/не реализованы. Mock expiry/reconnect тесты не являются таким испытанием. Production PATAS/OmniRoute, общие настройки и ключи не изменялись; GitHub не обновлялся. Пользовательское приложение не запускает сессию автоматически и всё ещё требует сохранённого отдельного финансового предела.

Детальные локальные записи находятся в `../public-acceptance/RESULT.json` (вне git-проекта), `run-01/EVENTS.json`, `reply-recheck/RESULTS.json`, `native-quiet/RESULT.json`.

Аудит возврата: механизма release/refund в ledger нет; все 7 новых платных текстовых запросов вернули результаты. Неиспользованные $0.05 первоначального потолка .30 никогда не резервировались (ledger записал .25, одноразовый runtime завершён). Повторная проверка добавила .10, поэтому фактический новый текстовый резерв .35. Полный read-only аудит: `public-acceptance/BUDGET-AUDIT.json`; никаких ledger-файлов он не изменил.
