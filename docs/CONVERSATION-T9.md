# Trailk 1.2.0 · T9 для разговора

Основной экран: перевод слева, 2–3 коротких варианта ответа EN+RU справа. Они появляются автоматически по словам собеседников; писать мысль и нажимать «Предложить ответ» для этого не нужно. Выбранный английский можно изменить и прочитать. Отправки и озвучивания нет. «Своя мысль → английский» — дополнительный способ, если хочется сказать своё.

## Запуск и стоимость

Выбора минут и окна «Перед началом» нет. Подключение Zoom → OpenAI сохраняется в настройках; запуск всегда только по кнопке «Начать», остановка по «Остановить». Пользователь уже явно разрешил этот источник/провайдера и опциональный микрофон. Микрофон остаётся выключенным и технически не подключён.

Денежный предел нельзя отменять вместе с выбором длительности. При обновлении согласие на источник сохраняется, а **пределы расходов нужно один раз сохранить** в «Подключение и настройки»: аудио и отдельный резерв текстовых запросов. Без этого «Начать» открывает настройки и показывает причину; не запускает пустую или скрыто платную сессию. В стартовом состоянии лимиты предложены $1.13 аудио и $0.50 текста, но агент их финансово не подтверждает. Старые исчерпанные test-ledger/approval/STOP файлы не сбрасываются и не удаляются. После сохранения пользовательских пределов новая сессия получает отдельный резерв; прежний test-ledger не делает T9 молча неактивным.

Аудио оценивается по $0.034/мин включая передаваемую тишину. Текстовый резерв — $0.05 на попытку: $0.50 допускает до 10 обновлений, $2 — до 40. Резерв не равен списанию; фактический счёт не известен. Поддерживаются те же предельные настройки $10 аудио/$2 текста: не бесконечные расходы. Сессия длится до Stop, денежного предела, ошибки либо ограничения ресурсов, без произвольного пользовательского лимита 150 секунд/90 минут. Внутренний защитный срок рассчитывается из выбранной суммы и проверенной цены; учитываются также отправленные PCM-байты. Это ограничение расчётной стоимости, не гарантия точного провайдерского биллинга.

## Автоматическое обновление подсказок

- Используется услышанный **перевод собеседников**, поскольку source transcription отдельно не подключён и его доплата не заявляется бесплатной.
- После законченной по тексту фразы или локально наблюдаемой паузы ждём 1.6 секунды устойчивости. Нет документированного server turn-final: это клиентская эвристика готовности текста, не определение человека/события конца реплики от API.
- Не чаще одного запуска в 12 секунд, один запрос одновременно, контекст до 2400 символов из последних наблюдений. Это ограничитель частоты, не обещание задержки ответа.
- Любой новый фрагмент текста делает прежний результат потенциально устаревшим. Устаревший ответ не показывается; очередь содержит только актуальный контекст, одинаковый контекст не повторяется после ошибки. Stop немедленно запрещает новые запуски и показ запоздавшего результата. Уже отправленный запрос нельзя считать отменённым у провайдера/бесплатным.
- Блоки вариантов добавляются без переписывания старых. При чтении/фокусе/наведении сохраняется позиция; свежие варианты отмечены, старые — помечены. Выбранный английский не меняется автоматически. Последний уже зарезервированный запрос может отобразиться после исчерпания остатка, новые запросы блокируются.
- Модель получает правила не выдумывать факты, согласие, обещания пользователя или то, что он уже сказал. Продолжение речи собеседника и выбор карточки не считаются собственным ответом пользователя. Это правила/валидация, не гарантия качества модели.

## Соединение и сохранение аудио-последовательности

Используется dedicated `/v1/realtime/translations`, 24 kHz mono PCM16, ~200 ms пакеты, **включая тишину**. Нельзя вырезать тишину: она влияет на время модели. Числовой общий предел API не выдуман из generic Realtime 60 минут.

При наличии `session.created/updated.session.expires_at` готовится новое соединение того же источника/провайдера за 40 секунд до указанного API срока. За 10 секунд до срока старому отправляется `session.close`, затем до 8 секунд читается хвост до `session.closed`; только после этого аудио идёт в готовое новое соединение. Общий счётчик байтов/резерв не обнуляется. PCM каждой позиции отправляется один раз. Между соединениями небольшой ограниченный RAM-буфер до 10 секунд; переполнение останавливает capture. История и контекст T9 остаются в памяти. Возможны задержка/потеря хвоста при ошибке — бесшовность или нулевая задержка не обещаны.

Неверный/слишком близкий expiry, неподготовленная/неудачная смена, отсутствие подтверждённого хвоста, неожиданный обрыв или ошибка — безопасная остановка без автоматического повторения уже отправленного звука. Если API не вернул expires_at, используется одно соединение до Stop/лимита/закрытия, без выдуманного таймера. Это не бесконечное API-соединение. Уникальность дельт определяется event_id в рамках соединения; elapsed_ms — только приблизительное выравнивание, несколько дельт могут иметь одинаковое значение. Безусловные пробелы между дельтами не вставляются.

## Кто говорит и микрофон

Сейчас единственный фактический канал — смешанный output Zoom, помеченный **«Собеседники»**. Абзацы по пунктуации/паузы не превращаются в «Человек 1/2». Подготовлена схема устойчивых меток только при подтверждённом isolated channel или finalized diarization; сам такой backend не подключён. Optional own-mic схема допускает «Я» только для действительно изолированного собственного канала. Без него приложение не слышит устные ответы пользователя и не угадывает их по продолжению разговора.

Микрофон и настоящая диаризация не реализованы; T9 работает без них. Возможные будущие пути: Zoom RTMS с реальными participant tracks/IDs (отдельная Zoom app/host/admin setup) или отдельно разрешённый провайдер live diarization. В этом выпуске нет Deepgram, нового провайдера или новых постоянных credentials. Разрешение на optional mic получено, но ОС не запрашивалась и поток не активирован.

## Проверки и пределы доказательства

52 Python-теста и 15 JS-тестов проверяют денежную границу до key read, отсутствие неразрешённого контекста, одноразовый резерв, обновление expiry, полную непрерывную последовательность уникальных PCM-позиций через несколько mock WebSocket, общий бюджет, закрытие/drain, отмену медленной подготовки, отказ без retry, 90 минут виртуального PCM, автоматический debounce/throttle/dedup/obsolete, последний оплаченный результат и честные speaker evidence.

25 проверок реального AppKit/WKWebView окна покрывают автоматический T9 без ручного ввода/кнопки ответа, сохранение прочитанного/выбранного текста, font/scroll, Start/Stop, повторные клики, отсутствие стартового popup/поля минут, настройки/отмену и ручное восстановление локального сервера. UI verification дополнительно программно блокирует реальные платные маршруты, native capture и Keychain. При завершении runner явно останавливает собственный backend перед выходом; первоначальный runner завис после записи успешного отчёта и был исправлен/перепроверен. Отдельная проверка подтверждает автоматическое появление карточки при пустых полях мысли/английского, без кнопки запроса. Найденная двойная задержка стабилизации устранена.

Реальный Zoom, качество подсказок, точный биллинг, изоляция аудио/эхо, реальное обновление API-сессии, AirPods/device changes и длительный звонок не проверялись. Mock/виртуальное время не являются измерением качества или реальной задержки.
